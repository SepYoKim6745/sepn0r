## 오늘의 학습 목표

- 🟢 **목표 1:** 검색과 AI 리서치의 차이를 이해하고 좋은 리서치 프롬프트 5요소를 작성할 수 있다
- 🟢 **목표 2:** 보고서 요약 4가지 유형(결론/브리핑/구조/인용)을 독자에 맞춰 선택할 수 있다
- 🟢 **목표 3:** 회의록을 4슬롯(안건/논의/결정/액션)으로 구조화하고 3W로 검증할 수 있다

- 🟢 **목표 5:** 보고서 4유형(분석/제안/현황/비교)에 맞는 골격을 설계하고 AI에게 다듬기를 시킬 수 있다
- 🟢 **목표 6:** 메시지 유형(비교/추세/구성/관계)에 맞는 시각화 도구를 선택하고 Mermaid로 다이어그램을 만들 수 있다

## 실습 1) 리서치 프롬프트 5요소 만들기 `난이도 1`

> **📌 미션:** 같은 주제라도 프롬프트 한 줄 차이로 결과 품질이 달라집니다. **목적·범위·시점·출처·형식** 5요소를 빠짐없이 채워서 리서치 프롬프트 1개를 작성하세요.

**Before — 막연한 요청 (이렇게 하면 안 됨)**

<details><summary>📋 나쁜 예시 보기</summary>

```
전기차 시장에 대해 조사해줘.
```

**결과:**
- 일반론 — "전기차 시장은 빠르게 성장하고…"
- 시점 불명 — 작년 자료인지 올해인지 모름
- 출처 없음 — 어디서 가져온 정보인지 불명
- 깊이 부족 — 보고서로 쓸 수 없는 수준

</details>

**5요소 체크리스트:**

| 요소 | 의미 | 예시 |
|------|------|------|
| 목적 | 왜 조사하는가 | 임원 보고용 / 의사결정용 |
| 범위 | 지역·산업·기간 | 한국 HR Tech, 매출 100억 이하 |
| 시점 | 최신 6개월 / 특정 연도 | 2024~2025년 자료 한정 |
| 출처 요건 | URL 필수 / 공공·언론·학회 우선 | URL 포함, 공공기관 우선 |
| 결과 형식 | 표 / 한 페이지 / 5문단 | 한 페이지 표 + 핵심 요약 5문장 |

<details><summary>✅ 정답 예시 — 5요소를 모두 채운 프롬프트</summary>

```
당신은 B2B SaaS 시장 분석가입니다.

[목적] 임원 보고용 시장 진단 보고서 초안 작성
[범위] 한국 HR Tech 시장, 매출 100억 이하 기업
[시점] 2024~2025년 자료에 한정
[출처] URL 필수, 공공·언론·학회 우선
[형식] 한 페이지 표 + 핵심 요약 5문장

확인되지 않는 수치는 "확인 불가"로 표기하세요.
```

**결과:**
- 정책 변화 시점·금액이 표로 정리
- 각 항목에 출처 URL 함께 제공
- 보고서 초안에 바로 붙여 쓸 수 있는 수준

</details>

## 실습 2) 출처 검증 4단계 체크리스트 `난이도 1`

> **📌 미션:** AI가 제시한 출처는 그럴듯해 보여도 가짜일 수 있습니다. 보고서에 쓰기 전 4단계로 반드시 검증하세요.

**환각의 3가지 모습:**

| 유형 | 예시 |
|------|------|
| 가짜 통계 | "국내 시장 23.4% 성장" — 출처 없음 |
| 가짜 인용 | 존재하지 않는 논문 제목·저자 제시 |
| 잘못된 URL | 그럴듯하지만 클릭하면 404 |

**4단계 검증 워크플로:**

| 단계 | 확인 항목 | 방법 |
|------|------|------|
| 01 | URL 직접 클릭 | AI가 제시한 링크를 실제로 열어본다. 404·다른 페이지면 즉시 폐기 |
| 02 | 작성자·발행처 확인 | 기관·언론사·학회인지 개인 블로그인지 도메인부터 확인 |
| 03 | 발행 시점 확인 | "2025년 자료"라고 했어도 원문에서 직접 발행일을 본다 |
| 04 | 교차 검증 | 핵심 수치는 최소 2개 출처에서 같은 값이 나오는지 확인 |

> ⚠️ **검증 안 된 인용은 차라리 빼는 것이 낫다. 보고서의 신뢰는 가장 약한 출처에서 무너진다.**

<details><summary>📋 검증 프롬프트 예시 (CoVe 활용)</summary>

```
[1차 답변에서 받은 출처 5개를 붙여넣기]

위 출처들에 대해 다음을 점검하세요:
1. 각 URL의 도메인이 공공·학술·주요 언론인가?
2. 각 인용 수치가 원문에 실제로 등장하는가?
3. 발행 연도가 [목표 시점]과 일치하는가?
4. 동일 수치가 다른 출처에서 같은 값으로 확인되는가?

확인 불가 항목은 ❌ 표시하고 폐기 권고하세요.
```

</details>

## 실습 3) 보고서 요약 — 독자별 3가지 변환 `난이도 2`

> **📌 미션:** 같은 보고서도 누가 읽느냐에 따라 다른 요약이 필요합니다. 본인이 자주 보는 보고서·논문·매뉴얼 1개를 준비하고, **임원용 1줄 / 실무자용 5문단 / 협업자용 구조형** 3가지 요약을 만드세요.

**요약 4가지 유형:**

| 유형 | 분량 | 용도 |
|------|------|------|
| Executive (결론 요약) | 한 줄 결론 + 핵심 리스크 1~2개 | 임원·의사결정자용 |
| Briefing (브리핑 요약) | 5문단 내외, 액션·다음 단계 | 실무 협업·회의 자료 |
| Structural (구조 요약) | 목차·논리·근거 흐름 | 긴 보고서 사전 파악 |
| Quote (인용 요약) | 원문 핵심 문장 그대로 보존 | 법·정책·계약 문서 |

**Before — 막연한 요청**

```
이 보고서 요약해줘.
```

→ 누구에게 보낼지 모르는 일반 요약, 분량 제멋대로(3줄~30줄), 결론·액션·근거 구분 없이 섞임

<details><summary>✅ 정답 예시 — 임원용 1줄 요약 프롬프트</summary>

```
[첨부] 분기_실적_보고서.pdf

이 보고서를 임원 보고용으로 요약해주세요.

[유형] 임원 보고용 결론 요약
[분량] 한 줄 결론 + 핵심 리스크 3개
[형식] 표 (항목 / 내용 / 근거 페이지)
[제약] 원문에 없는 내용은 추가 금지

수치는 원문 페이지를 함께 표기.
```

**결과 예시:**
- 한 줄 결론 → 슬라이드 표지로 사용 가능
- 리스크 3개 → 보고서에 그대로 삽입
- 근거 페이지 → 즉시 검증 가능

</details>

<details><summary>✅ 정답 예시 — 실무자용 5문단 요약 프롬프트</summary>

```
[첨부] 분기_실적_보고서.pdf

이 요약은 [실무 팀장]에게 전달됩니다.

[유형] 브리핑 요약
[분량] 5문단 내외
[형식] 배경 / 핵심 결과 / 액션 / 다음 단계 / 리스크
[제약] 각 문단 4문장 이내
```

</details>

<details><summary>✅ 정답 예시 — 협업자용 구조형 요약 프롬프트</summary>

```
[첨부] 분기_실적_보고서.pdf

이 요약은 [신규 합류자]에게 전달됩니다.

[유형] 구조 요약
[형식] 전체 목차 + 각 챕터 한 줄 요약
[제약] 원문 페이지 번호와 매핑
```

</details>

> 💡 **분량별 처리 전략:** 30쪽 이하 → 통째 첨부 / 30~100쪽 → 챕터별 분할 후 통합 / 100쪽 이상 → 목차 추출 → 핵심 챕터만 선택 요약 (Lost in the Middle 회피)

## 실습 4) 회의록 4슬롯 구조화 `난이도 2`

> **📌 미션:** 시간순 받아쓰기는 회의록이 아닙니다. 최근 회의 메모 1개를 **안건 / 논의 / 결정 / 액션** 4슬롯으로 재배치하세요.

**4슬롯 구조:**

| 슬롯 | 핵심 질문 | 빈 채워야 할 정보 |
|------|------|------|
| Agenda (안건) | 무엇을 논의할 것인가 | 오늘 다룰 주제 |
| Discussion (논의) | 어떤 관점이 오갔는가 | 누가 어떤 의견을 |
| Decision (결정) | 무엇이 결정되었는가 | 확정된 방향 |
| Action (액션) | 누가 무엇을 언제까지 | 담당자·산출물·기한 |

> ⚠️ **4슬롯 중 결정과 액션이 비어 있으면, 회의는 다시 열려야 함.**

<details><summary>📋 Before — 시간순 받아쓰기 (잘못된 예)</summary>

```
10:00 김차장 — Q3 매출 그래프 보여줌
10:05 박팀장 — "좀 어렵겠는데?"
10:10 이대리 — 채널을 바꿔야 한다는 의견
10:15 김차장 — "그럼 어떻게 할까요"
10:20 박팀장 — "일단 다음주까지 정리해서"
10:25 이대리 — "제가 한번 정리해 보겠습니다"
```

**문제점:**
- 누가 결정했는지 불명
- 액션이 누구 몫인지 모호
- 그대로 공유해도 후속 조치 어려움

</details>

<details><summary>✅ 정답 예시 — 4슬롯 변환 프롬프트</summary>

```
아래 회의 내용을 4슬롯(안건/논의/결정/액션)으로 구조화해주세요.

[조건]
- 결정·담당자·기한 모두 명시
- 액션은 "@이름 — 무엇을 — 언제까지" 형식
- 회의에서 결정되지 않은 항목은 "결정 보류"로 표기
- 추측·창작 금지

---
[원본 메모]
10:00 김차장 — Q3 매출 그래프 보여줌
10:05 박팀장 — "좀 어렵겠는데?"
10:10 이대리 — 채널을 바꿔야 한다는 의견
10:15 김차장 — "그럼 어떻게 할까요"
10:20 박팀장 — "일단 다음주까지 정리해서"
10:25 이대리 — "제가 한번 정리해 보겠습니다"
```

**기대 결과:**

```
[안건] Q3 매출 부진 대응
[논의] 채널 다변화 부재 (이대리)
       실행 부담 우려 (박팀장)
[결정] 채널 전략 재검토 진행
[액션] @이대리 — 채널별 매출 분석안 — 다음주 화요일까지
```

</details>

> 💡 **음성·녹취 처리 4단계 파이프라인:** STT 텍스트화 (Clova Note·Whisper) → 화자 분리 → 4슬롯 구조화 지시 → 3W 검증

## 실습 5) 액션아이템 3W 검증 `난이도 1`

> **📌 미션:** 액션아이템이 진짜 액션인지, 그냥 의견인지 3W로 검증하세요.

**3W 체크리스트:**

| 항목 | 좋은 예 ✅ | 나쁜 예 ❌ |
|------|------|------|
| WHO (누가) | @이대리, @박팀장 | "관련 부서가", "담당자가" |
| WHAT (무엇을) | 채널별 매출 분석안 작성 | "검토해 보기로", "살펴보기로" |
| WHEN (언제까지) | 2026-06-16 (화) 18시까지 | "다음에", "빠른 시일 내에" |

> ⚠️ **3W 중 하나라도 빠지면 "액션"이 아니라 "의견"입니다.**

<details><summary>📋 검증 프롬프트 예시</summary>

```
아래 액션아이템 목록을 3W로 검증해주세요.

[검증 기준]
- WHO: 특정 개인이 명시되었는가?
- WHAT: 구체적 산출물·행동이 있는가?
- WHEN: 구체적 날짜·시간이 있는가?

빠진 항목은 ❌로 표시하고, 어떻게 보완해야 하는지 1줄 제안.

---
[액션아이템 목록]
- 관련 부서가 시장 트렌드를 살펴본다
- 이대리가 분석안을 빠른 시일 내에 작성
- @박팀장 — Q4 예산안 — 2026-06-16까지
```

</details>

## 실습 6) 직무 맥락 번역 + 역번역 `난이도 2`

> **📌 미션:** 같은 영어도 직무에 따라 다른 한국어가 됩니다. 영문 메일/문서 1단락을 가져와서 **직무 맥락 번역 + 역번역**으로 의미 손실을 잡으세요.

**같은 단어 다른 의미 — Margin (마진)**

| 분야 | 의미 | 예시 |
|------|------|------|
| 금융/상거래 | 이익률 | "마진이 박하다" → 돈이 안 된다 |
| 디자인/인쇄 | 여백 | 종이 테두리에서 본문까지의 빈 공간 |
| 의료 (수술) | 절제연 | "마진이 깨끗하다" → 암세포가 남지 않음 |

**톤 통제 5요소:**

| 요소 | 의미 | 예시 |
|------|------|------|
| Audience | 누구에게 전달되는가 | 30대 한국 직장 여성 |
| Industry | 어떤 분야의 표준 용어 | 프리미엄 스킨케어 브랜드 |
| Formality | 공식 / 친근 / 중립 | 친근하고 따뜻한 톤 |
| Style | 문장 길이·구조 | 짧고 감성적인 문장 |
| Terms | 핵심 단어 매핑 사전 | premium → 프리미엄, exclusive → 특별한, elegant → 우아한 |

<details><summary>📋 Before — 직역만 (안 좋은 예)</summary>

```
다음 영문 계약 조항을 한국어로 번역해줘:
"This Agreement shall be governed by and construed
in accordance with the laws of the Republic of Korea."
```

## 실습 12) 골격에 글 채우기 + AI 다듬기 `난이도 2`

> **📌 미션:** 이전 실습에서 만든 골격에 본문 초안을 직접 작성한 뒤, AI에게 **구체적 첨삭 프롬프트**로 다듬게 하세요.

**영역마다 다른 글쓰기 패턴:**

| 영역 | 목적 | 글쓰기 방식 | 예시 |
|------|------|------|------|
| 결론 | 의사결정 유도 | 단정적 1줄, 숫자 + 이슈 명시 | "매출 +12%, 채널 다변화 시급." |
| 인사이트 | 결론 뒷받침 | 불릿 3~5개, 각 항목 [Source N] | "① 신규 채널 56% [S1, 3]" |
| 외부 맥락 | 비교·검증 | 짧은 단락 2~3줄, 외부 출처 명시 | "한국 시장 +8%, 우리는 +12%로 상회." |
| 후속 과제 | 행동 유도 | 동사로 시작, 담당·기한 명시 | "채널 전략 수립 (Q4 첫 주, 마케팅팀)" |

**좋은 문장 3원칙:**

1. **짧게** — 한 문장에 한 메시지
2. **구체적으로** — 숫자·고유명사로 모호함 제거
3. **능동적으로** — 주어가 행동하는 능동태

**나쁜 문장 → 좋은 문장 5쌍:**

| 패턴 | ❌ 나쁜 문장 | ✅ 좋은 문장 |
|------|------|------|
| 수치 누락 | "매출이 다소 증가했습니다." | "매출 +12% 증가, 분기 최고치." |
| 수동태 | "검토되어야 할 것으로 사료됨." | "팀이 다음 주까지 검토." |
| 모호한 양화 | "여러 요인이 있을 수 있음." | "환율·물류비·경쟁사 3가지 요인." |
| 장식어 과다 | "매우 긍정적으로 작용할 것으로 보임." | "신규 가입자 +8천명 효과." |
| 완곡어법 | "다소 어려움이 있어 보입니다." | "현재 인력으로 12월 마감 불가." |

> 💡 **3가지 자기 점검 질문:** 의심스러우면 — 숫자가 있나? · 누가 하나? · 한 줄로 더 짧게?

<details><summary>📋 Before — 모호한 다듬기 프롬프트</summary>

```
이 글 좀 다듬어줘
```

→ 결과 무작위. AI가 어떻게 다듬어야 할지 모름.

</details>

<details><summary>✅ 정답 예시 — 구체적 첨삭 프롬프트</summary>

```
다음 문단을 [결론] 영역에 맞게 다듬어주세요.

[원본]
"Q3 매출이 좋아진 것 같습니다. 단, 일부 우려스러운 부분도 있어
향후 검토가 필요해보입니다."

[조건]
- 길이: 1줄 (50자 이내)
- 톤: 임원 보고용 (격식)
- 원칙: 숫자 포함, 능동태
- 원본 의미는 유지

[기대 결과 예시]
"Q3 매출 +12% 성장, 단 신규 채널 의존도 56% — 다변화 시급."
```

</details>

**AI 다듬기 4단계 워크플로:**

| 단계 | 누가 | 할 일 |
|------|------|------|
| 01 Draft | 사람 | 골격 영역에 초안을 직접 작성 |
| 02 Edit | AI | 구체적 첨삭 프롬프트로 개선 (영역/길이/톤/원칙 명시) |
| 03 Review | 사람 | AI 결과 100% 신뢰 X — 수치·고유명사·뉘앙스 점검 |
| 04 Finalize | 사람 | 출처·일관성·수치 점검하고 최종본 확정 |

> ⚠️ **4단계 중 3단계가 사람의 몫. AI 결과를 그대로 쓰면 자기 글이 아닌 "AI 글"이 됨.**

## 실습 13) 팀 프로젝트 — "자습 빠지고 일찍 귀가" 명분 보고서 `난이도 3`

> **📌 미션:** 오늘 자습을 빠지고 일찍 귀가해야 하는 그럴듯한 사유를 한 페이지 보고서로 작성해 강사(결재자)에게 제출하세요.

**작업 규칙:**

| 항목 | 내용 |
|------|------|
| 사유 | 팀별 자유 — 창의적이되 진짜 결재 받는다는 마음으로 |
| 근거 | 학술 논문·언론 기사·공공 통계로 뒷받침 |
| 도구 | NotebookLM · Perplexity · 검색 활용 |
| 분량 | 한 페이지 안에 결론·근거·맥락·후속 과제 모두 |

**근거 자료 예시:**

| 카테고리 | 검색 키워드 |
|------|------|
| 의학·심리학 논문 | "수면 부족이 학습·집중에 미치는 영향", "두통과 인지 능력 저하 연구" |
| 뉴스·산업 보고서 | "오후 시간 학습 효율 저하" 기사, "분산 학습이 효과적이라는 연구 보도" |
| 공공 통계·기관 자료 | 통계청 통근시간 데이터, 교육부 학습환경 보고서 |

**4단계 통합 워크플로:**

| 단계 | 활용 도구·기법 |
|------|------|
| 01 Research | 검색 · NotebookLM · Perplexity로 사유의 근거 자료 수집 (Chapter 1·2) |
| 02 Structure | 결론 → 근거 → 맥락 → 후속과제 4영역으로 골격 설계 (실습 11) |
| 03 Write | 영역별 글쓰기 패턴 + 좋은 문장 3원칙 적용 (실습 12) |
| 04 Polish | AI 첨삭 프롬프트로 다듬기 + 팀원 검토 + 최종본 확정 (실습 12) |

**제출 전 6항목 체크리스트:**

| # | 체크 항목 | 왜 중요한가 |
|---|------|------|
| 01 | 결론이 첫 줄에 있는가? | 결재자가 첫 줄만 보고 결정 가능 |
| 02 | 근거에 학술·언론 출처가 있는가? | 주관적 변명이 아닌 객관적 근거 |
| 03 | 외부 맥락(보강 정보)이 있는가? | 사유의 일반성·심각성 입증 |
| 04 | 문장이 짧고 구체적인가? | 수치·고유명사로 모호함 제거 |
| 05 | 후속 과제에 행동 동사가 있는가? | "내일 보충 학습" 같은 만회안 제시 |
| 06 | 한 페이지 안에 들어가는가? | 결재자 시간을 빼앗지 않음 |

> 💡 **"수면 부족" 같은 단순 사유도 학술·통계 출처가 붙으면 "그럴듯한 보고서"로 격상됩니다. 진짜 사유 X 진짜 출처 X 진짜 결재의 압박감을 느끼며 만드세요.**

<details><summary>✅ 정답 예시 — 통합 프롬프트 (NotebookLM에서 최종 출력)</summary>

```
업로드한 학술·뉴스·통계 자료들을 종합해서
"오늘 자습 면제 + 조기 귀가" 사유 보고서를 한 페이지로 작성해주세요.

[구조]
1. Headline — 결론 1줄 (행동 + 이유 + 만회안)
2. Key Findings — 학술·통계 근거 3개 (각 [Source N])
3. Context — 일반성·심각성을 보여주는 외부 맥락 2~3줄
4. Next Steps — 만회안·다음 단계 2~3개 (담당·기한)

[제약]
- 자료에 없는 내용 추가 금지
- 결론은 한 줄, 단정적 문장
- 문장은 짧고 구체적, 능동태
- 한 페이지 안에 모두
```

</details>

## 실습 14) 데이터 1개 → 적합한 시각화 선택 `난이도 2`

> **📌 미션:** 본인 데이터(또는 공공 데이터)를 1개 가져와서 메시지 유형에 맞는 시각화를 AI에게 만들게 하세요.

**메시지 유형 4종 → 차트 매핑:**

| 메시지 유형 | 핵심 질문 | 추천 차트 |
|------|------|------|
| Comparison (비교) | "A가 B보다 큰가?" | 막대 차트 (수직·수평) |
| Trend (추세) | "시간 따라 어떻게 변했나?" | 라인 차트 |
| Composition (구성) | "전체 중 부분 비중은?" | 도넛 차트 (3~5개 항목까지만) |
| Relationship (관계) | "X와 Y가 연관되나?" | 산점도 |

**3가지 도구 — 표·차트·다이어그램:**

| 도구 | 정확한 수치 | 시각적 패턴 | 구조·흐름 |
|------|------|------|------|
| Table (표) | ⭐⭐⭐ | ⭐ | ⭐ |
| Chart (차트) | ⭐ | ⭐⭐⭐ | ⭐ |
| Diagram (다이어그램) | — | ⭐ | ⭐⭐⭐ |

**흔한 실수 — 차트가 메시지를 흐릴 때:**

| 실수 | 결과 |
|------|------|
| 추세를 파이 차트로 | 시간 정보 사라짐 |
| 10+ 카테고리 파이 | 슬라이스 분간 불가 |
| Y축 부풀리기 | 작은 차이가 커 보임 |
| 화려한 대시보드 | 메시지가 디자인에 묻힘 |

> ⚠️ **예쁜 차트가 메시지를 흐린다. 가장 단순한 차트가 가장 좋은 차트.**

<details><summary>📋 Before — "차트 만들어줘" (안 좋은 예)</summary>

```
이 데이터로 차트 만들어줘
```

→ AI가 메시지를 모르므로 무작위로 그래프 형태 선택.

</details>

<details><summary>✅ 정답 예시 — 시각 자료 프롬프트 4요소</summary>

```
다음 [데이터]로 [메시지]를 강조하는 [형식]을 만들어줘.

[데이터]
지역: 서울 320, 부산 280, 대전 220, 광주 180

[메시지]
서울이 가장 크다는 점이 한눈에 보이게

[형식]
Markdown 표 + 막대 차트 추천

[스타일]
단순하게, 화려한 색은 빼고
```

**4요소 체크:**
1. 데이터 (Data) — 실제 숫자·표를 그대로 붙여넣기
2. 메시지 (Message) — 무엇을 강조할지
3. 형식 (Format) — 출력 형태 명시 (Markdown 표 / 막대 / 도넛 등)
4. 스타일 (Style) — 단순함·색·톤

</details>

> 💡 **AI는 이미지를 직접 그리지 않는다. 표는 Markdown, 다이어그램은 Mermaid 코드, 차트는 Gemini 코드 인터프리터로 PNG.**

## 마무리 — 4단계 통합 워크플로 정리

| 단계 | 활용 챕터 | 핵심 도구 |
|------|------|------|
| 01 Research | Chapter 1 | 검색 · NotebookLM · Perplexity |
| 02 Structure | Chapter 3 (3-1) | AI에게 "골격만 만들어줘" |
| 03 Write | Chapter 3 (3-2) | 영역별 패턴 + 3원칙 |
| 04 Polish | Chapter 3 (3-2) + Chapter 4 | AI 첨삭 + 시각화 |

**핵심 정리 3가지:**

1. **검색 ≠ AI 리서치** — AI는 자료를 가져오는 동시에 읽고 정리한다. 환각은 4단계 출처 검증으로 잡는다.
2. **글 시키지 말고 골격을 시켜라** — 보고서는 구조가 80%. 영역(결론·근거·맥락·후속) + 한 줄 요약을 먼저 잡는다.
3. **출처가 곧 신뢰** — `[Source N]` + `[Perplexity]` 인용으로 검증 가능한 보고서를 만든다.

> 🎯 **최종 미션:** 내 직무에서 가장 자주 만드는 문서 1개를 골라, 오늘 배운 4단계 워크플로를 적용해 30분 안에 한 페이지 보고서를 완성해보세요.
